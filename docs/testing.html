Testes

Testar RPC com hardware real (pinpad, impressora) é caro e lento. O setup atual hospeda o Sample.Server.Api via WebApplicationFactory e usa conexões SignalR in-memory — caller e agente vivem no processo do teste, exatamente o mesmo caminho de código de produção (menos o TCP).

Rodar

dotnet test tests/Rpc.IntegrationTests

7 testes, ~40s. Cobertura por cenário:

TesteO que verifica
Caller_invokes_server_side_handler_via_RpcAddress_Server Caso 1: caller → handler local no servidor.
Caller_invokes_agent_via_RpcAddress_Device Caso 2: caller → agente específico por DeviceId.
Caller_invokes_agent_via_RpcAddress_Role_for_capability Caso 4: roteamento por capability+tenant para o primeiro agente disponível.
Caller_invokes_agent_via_RpcAddress_User_for_user_plus_capability Caso 3 fluxo feliz: duplex completo, troca de mensagens, TefCompleted.
Tef_caller_cancellation_propagates_to_agent_loop Caso 3 cancelamento: o token do agente é cancelado quando o caller cancela.
Invoke_to_offline_device_throws_RouteNotFound Erro de roteamento quando o device alvo não está conectado.

A fixture

RpcTestFixture herda WebApplicationFactory<Program> apontando pro Sample.Server.Api. Habilita EnableDetailedErrors no SignalR pra facilitar diagnóstico e expõe dois helpers: 

// abre HubConnection in-memory contra o test server
await using var caller = await fixture.ConnectAsync(deviceId: "caller-1");

// agora com capabilities e dispatchers (este Hub agora é também um agente)
var agentDispatchers = new DispatcherRegistry();
PosTerminalDispatcher.Register(agentDispatchers, new TestPosTerminal("agent-A"));

await using var agent = await fixture.ConnectAsync(
    deviceId: "agent-A",
    capabilities: [Capability.PosTerminal],
    agentDispatchers: agentDispatchers);

O fixture.ClientFor(connection) devolve um IRpcClient com todos os proxies registrados, pronto pra invocar.

Exemplo: teste do fluxo TEF completo

[Fact]
public async Task Caller_invokes_agent_via_RpcAddress_User_for_user_plus_capability()
{
    await using var fixture = new RpcTestFixture();

    var tefDispatchers = new DispatcherRegistry();
    TefServiceDispatcher.Register(tefDispatchers, new TestTefServiceImpl());

    await using var agent = await fixture.ConnectAsync(
        deviceId: "pdv-01",
        userId: "operator-1",
        capabilities: [Capability.Tef],
        agentDispatchers: tefDispatchers);

    await using var caller = await fixture.ConnectAsync(deviceId: "blazor-session-1");
    var rpc = fixture.ClientFor(caller);
    var tef = rpc.For<ITefService>(RpcAddress.User("operator-1", Capability.Tef));

    await using var call = tef.Charge(new TefRequest(50m, "operator-1", "REF1"), default);

    var seen = new List<TefEvent>();
    var done = new TaskCompletionSource<TefCompleted>(TaskCreationOptions.RunContinuationsAsynchronously);

    _ = Task.Run(async () =>
    {
        await foreach (var ev in call.Responses)
        {
            seen.Add(ev);
            switch (ev)
            {
                case TefCollectInput: await call.SendAsync(new TefResponse("12345678901")); break;
                case TefMenu:         await call.SendAsync(new TefResponse("1")); break;
                case TefConfirm:      await call.SendAsync(new TefResponse("S")); break;
                case TefCompleted ok: done.TrySetResult(ok); break;
                case TefError err:    done.TrySetException(new InvalidOperationException(err.Message)); break;
            }
        }
    });

    var completed = await done.Task;
    Assert.Equal("123456", completed.Nsu);
    Assert.Contains(seen, e => e is TefDisplayMessage);
}

Testando cancelamento

O teste de cancelamento expõe o token do agente através de um callback no impl de teste:

var agentCancelled = new TaskCompletionSource<bool>(TaskCreationOptions.RunContinuationsAsynchronously);
var impl = new TestTefServiceImpl
{
    OnStart = call => call.Token.Register(() => agentCancelled.TrySetResult(true))
};
// ... agente registrado com esse impl ...

using var cts = new CancellationTokenSource();
await using var call = tef.Charge(new TefRequest(10m, "u2", "X"), cts.Token);

// consome ao menos uma mensagem para garantir que o duplex está estabelecido
var enumerator = call.Responses.GetAsyncEnumerator(cts.Token);
await enumerator.MoveNextAsync();
await enumerator.DisposeAsync();

cts.Cancel();   // dispara a cadeia: caller → DuplexCancel → agente

var won = await Task.WhenAny(agentCancelled.Task, Task.Delay(TimeSpan.FromSeconds(10)));
Assert.Same(agentCancelled.Task, won);   // não foi timeout

Esse teste prova a invariante mais importante do duplex: cancelamento atravessa fronteiras de processo.

Dicas pra escrever seus próprios testes

  • Evite portas TCP. Use fixture.Server.CreateHandler() via a fixture; isso garante reprodutibilidade e velocidade.
  • Use timeouts gordos. SignalR + JSON + Channels podem somar 100-300ms só no setup; ajuste o timeout do teste pra 10-15s.
  • Sempre await using nas conexões e nos duplex calls — vazamento de Hub connections aborta testes futuros.
  • Implementações de teste em tests/.../Agents/ — replicam só o que importa pro caso. Não use as impls reais a menos que valha a pena.
  • Pra simular falha de agente: descarte o HubConnection do agente no meio do teste e verifique que o caller recebe OperationCanceledException ou erro com Kind = "RemoteException".

O que ainda não está testado

  • Reconexão automática durante chamada em voo (call/return deveria ser reenviado, duplex deveria falhar rápido).
  • Throughput: latência p99 sob carga concorrente (use BenchmarkDotNet em um projeto separado).
  • Recusa de confirmação pós-impressão (TEF desfaz).
  • Erro do pinpad real (rc != 0 não-cancelado).

Esses são candidatos diretos pra próxima rodada de testes.
