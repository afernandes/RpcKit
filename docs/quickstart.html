Quickstart

Em quatro comandos: compilar, testar, subir servidor + agente, abrir o navegador.

Pré-requisitos

  • .NET SDK 10.0.300 (versão pinada em global.json; rollForward: latestFeature permite patches).
  • Windows, macOS ou Linux. SignalR usa WebSocket sobre HTTPS — passa por proxy corporativo.
  • Sem dependência de Redis, banco ou broker para o cenário cloud-first padrão.

Passos

1. Compilar

dotnet build Rpc.slnx

9 projetos. Build limpo, sem warnings, em ~25s na primeira vez (NuGet restore) e ~5s incremental.

2. Rodar os 7 testes de integração

dotnet test tests/Rpc.IntegrationTests

Cobre os quatro casos do plano + cancelamento do duplex + roteamento para device offline.

O que prova: a fixture RpcTestFixture sobe o Sample.Server.Api via WebApplicationFactory e abre conexões SignalR in-memory para caller e agente. O caminho de código é o mesmo que vai pra produção — só não trafega TCP.

3. Subir servidor + Blazor

dotnet run --project samples/Sample.Server.Api

Boota o Hub em http://localhost:5XXX/rpc (porta no launchSettings.json) e o Blazor Server em /.

4. Subir agente local em outra janela

dotnet run --project samples/Sample.LocalAgent

O agente lê Rpc:HubUrl do appsettings ou usa http://localhost:5000/rpc por padrão. Conecta declarando capabilities tef, printer.kitchen e pos.terminal.

Para testar com mais de um agente, varie o DeviceId:

dotnet run --project samples/Sample.LocalAgent -- --Rpc:DeviceId=PDV-02 --Rpc:UserId=operator-2

5. Abrir o navegador

Vá até a raiz do servidor e clique pelas demos:

RotaO que demonstraCaso
/ordersIOrderService no servidor1
/pingPeer-to-peer com DeviceId2
/tefLoop CliSiTef completo na UI3
/printImpressão por capability + tenant4

Configuração do agente

O Sample.LocalAgent aceita estes valores (via appsettings.json, env vars ou CLI args):

ChaveDefaultUso
Rpc:HubUrlhttp://localhost:5000/rpcURL do Hub
Rpc:DeviceId<machine>:agentIdentificação única do device
Rpc:UserId—Para RpcAddress.User(...) resolver
Rpc:TenantId—Para RpcAddress.Role(...) filtrar
