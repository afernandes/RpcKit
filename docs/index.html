RpcKit

RPC bidirecional tipado para sistemas multi-superfície em .NET — MAUI (Windows/Android), ASP.NET, Blazor Server e agentes de hardware locais — usando SignalR como transporte único e uma camada fina de tipagem por cima.

Os quatro cenários, um único mecanismo

CASO 1

Cliente → Servidor

MAUI ou Blazor chama um handler tipado hospedado no ASP.NET. Endereço: RpcAddress.Server.

CASO 2

Cliente A → Cliente B

Peer-to-peer com o servidor como relay. Endereço: RpcAddress.Device("PDV-02").

CASO 3

Browser → TEF pinpad

Blazor dispara o loop interativo do CliSiTef no agente do PDV. Duplex bidirecional. RpcAddress.User(uid, Capability.Tef).

CASO 4

Browser → impressora

Roteamento por capability — qualquer agente do tenant que declarou aquela impressora. RpcAddress.Role(Capability.PrinterKitchen, tenantId).

Por que um mecanismo só

Os quatro casos são o mesmo problema arquitetural: invocar uma operação tipada num endpoint remoto identificado, com resposta. Diferem só em payload e endereçamento. Construir três stacks distintos (REST + gRPC + socket de impressora) triplica auth, reconexão, observabilidade.

SignalR resolve a parte difícil — transporte WebSocket sobre HTTPS, reconexão automática, scale-out, autenticação ASP.NET, streaming nativo. RpcKit adiciona o que falta: endereçamento tipado, roteamento por capability e duplex de primeira classe para loops interativos como o do CliSiTef.

Camadas em uma imagem

Contratos e Core são transport-neutros. SignalR fica nas extremidades. Trocar transporte (ex: LAN futura) muda só a camada de cima — contratos e proxies não.

Em 30 segundos — o caso TEF

O contrato modela o loop CliSiTef como duplex: o agente emite TefEvent a cada iteração; a UI envia TefResponse quando o operador responde. 

[RpcContract]
public interface ITefService
{
    [RpcMethod(Id = 1)]
    IDuplexCall<TefResponse, TefEvent> Charge(TefRequest initial, CancellationToken ct);
}

No componente Blazor:

await using var call = Rpc.For<ITefService>(
        RpcAddress.User(currentUserId, Capability.Tef))
    .Charge(new TefRequest(amount, userId, reference), ct);

await foreach (var ev in call.Responses.WithCancellation(ct))
{
    switch (ev)
    {
        case TefDisplayMessage m: ShowMessage(m.Text); break;
        case TefCollectInput ask:
            await call.SendAsync(new TefResponse(await PromptUser(ask)));
            break;
        case TefMenu menu:
            await call.SendAsync(new TefResponse(await PickMenu(menu)));
            break;
        case TefConfirm c:
            await call.SendAsync(new TefResponse(await Confirm(c) ? "S" : "N"));
            break;
        case TefCompleted ok: return ok;
        case TefError err: throw new TefException(err);
    }
}
A sessão é o par de canais. Sem transactionId correlacionando chamadas avulsas. Cancelar o CancellationToken derruba o loop atomicamente nos dois lados; desconectar o agente fecha a sessão e o Blazor recebe OperationCanceledException sem precisar de polling.
